## 0. 边界与已锁定的决策

第一轮的目标是**可跑通、可验证的核心闭环**，不是功能全集。仿真翻页、上下滚动、EPUB/PDF 渲染、
MOBI 解析等明确属于第二轮（M12），不会以"已完成"的名义呈现。

| 项 | 决定 |
| --- | --- |
| 服务端栈 | Node.js + TypeScript + SQLite（`node:sqlite`，零原生依赖） |
| 转码 | 服务端**不转码**，只做仓库；格式由 App 侧解析 |
| Android | Kotlin 原生，Compose UI + **自研分页引擎** |
| 阅读格式优先级 | **TXT 优先**（智能断章 + 自动目录 + 全套排版自定义） |
| 管理界面 | 服务端自带轻量 Web 管理页（`/admin/`，无打包器） |
| 部署目标 | NAS（x86_64 / linux/amd64）+ Docker |
| 手机访问 | 默认局域网 HTTP；用户有动态公网 IP ⇒ 必须给 HTTPS/加固路线 |
| 明确不做（本轮） | 按书 ACL、多租户私有库、用户间分享、分享链接、自助注册、2FA、OIDC/LDAP、OPDS、S3/SMB、DRM、音频书、正文全文检索、CRDT 多端并写 |

## 1. 进度总览

**M0–M11 全部完成并各自通过验收；M12 未开始。**

M11 之后另做了三轮**收口**（不属于任何里程碑）：周期清理任务（S1）、作者编辑闭环（S6）、
真机前自查修掉的三处（编码探测边界 / 封面渲染 / 开始阅读合并下载）。验收读数：

- sweeper：`test/sweeper.test.ts` 10 项；`npm run verify` **269 单测（21 文件）+ 28 冒烟 + 契约 62/28/32**。
- 作者编辑：`test/books-authors.test.ts` 10 项，**外加一次真浏览器驱动**（全新库 → 灌两本 TXT → 登录
  `/admin/` → 打开被判反的那本 → 作者框已预填 `三体` → 改成 书名 `三体` / 作者 `刘慈欣` → 保存 →
  **F5 重载后书架卡片仍是「三体 / 刘慈欣」** → 用真 HTTP `mode=replace` 重新导入同一个乱文件名，
  201、文件数 1→2，作者仍是 `刘慈欣`、`sort_key` 仍是 `刘慈欣 — 三体`，`pinned_fields_json` 含 `authors`）。
  这一趟还顺手撞出 S13（替换成相同字节会 500），并确认了列表与详情的作者顺序此前不一致
  ——`group_concat` 的 `ORDER BY` 写在了相关子查询上，SQLite 不保证按它喂给聚合，已改到聚合内部。
  **未验证**：截图式视觉确认（此环境的 in-app browser 无可见 surface，指针事件不可用，
  故点击由页面内 `element.click()` 派发，走的是同一批 handler）。
- **编码探测的样本边界**（一个 bug，两侧各写了一份）：`CharsetDetector` 与 `server/src/metadata/txt.ts`
  都只取前 64 KiB 做"严格 UTF-8"判定，切在一个多字节字符中间时合法文件也抛错，于是落到候选打分，
  而 GB18030 什么字节都能"解通"并胜出。实测用的是那本 97,628 字节的 UTF-8 测试书：整本严格解 OK、
  `subarray(0, 65536)` 严格解抛、按 GB18030 解出来的前 40 字与库里存的乱码简介逐字相同。
  修法是失败后先从尾部回退最多 3 字节再判（一个 UTF-8 序列最长 4 字节）。
  读数：服务端 `npm run verify` **270 单测**（+1）、28 冒烟全过；`:engine-core:test` **68 测试**（+1）。
  重新入库同一个文件后 `book_files.charset` 由 `GB18030` 变 `UTF-8`、`books.description` 是正常中文。
  App 侧把 `PIPELINE_VERSION` 2→3——v2 目录里存的是**按乱码文本切出来的 TOC**，不 bump 就永远读不到修复。
  模拟器重开这本书：正文正常、页眉「第零章 山雾」、TOC 缓存 30 行与原文 30 个 `第N章` 标题数一致
  （修复前是「第 1 部分」的定长兜底）。
- **TXT 封面在 App 里是空白**：服务端给无图格式存的是**生成的 SVG**，而 Coil 没注册 SVG 解码器——
  字节取到了、解不出来；`BookCover` 的本机色块又只在 `coverUrl` 为空时才画，于是渲染成一片空白。
  加 `coil-svg`（带进 `com.caverock:androidsvg-aar:1.4`）并在 `EbookdApp.newImageLoader` 注册
  `SvgDecoder.Factory()`，同时给 `AsyncImage` 补 `onError` 退回本机色块。
  读数：`assembleDebug` 出包，dex 里查到 `Lcoil3/svg/SvgDecoder` 与 `Lcom/caverock`；
  模拟器书架上封面画出来了（深色底 + 内框 + 完整四字书名 = 服务端那张 SVG，本机色块只有一个字）。
- **开始阅读自动下载**：详情页只剩「开始阅读」；`UnreadableBook` 带上可判别的 `reason`，
  `ReaderViewModel.downloadThenOpen` 入队后等 `observeTask` 到 `done` 再重开（一次请求只自动下载一次）。
  读数：`pm clear` → 重新登录 → 详情（只剩 开始阅读 / 自定义封面）→ 点一次 → 3 秒后阅读器打开，
  App 私有目录出现 `files/objects/d9/d97f….bin`（文件名就是服务端那个 blob 的 sha）、
  `download_task` 行 `state=done`；`:core:testDebugUnitTest` **69 测试 0 失败**（3 项 Live 仍跳过）。

> 上面三条的**未验证**部分：全部读数来自 API 36 模拟器，没有真手机；弱网与大文件下"正在下载…"的观感没测；
> `coil-svg` 只验过服务端自己生成的那种 SVG，EPUB 内封若是复杂 SVG 未测。

| A6 | 离线时标签与删除**刻意拒绝**（状态可以排队） | 这是设计决定：标签没有可比排序，排队等于发明一个没人要求的合并规则 |
| A7 | 离线设置的自定义封面不会自动重推，要用户回网后再点一次 | 文案里已说明 |
| A8 | **没有"一键改码"界面**（`04-Android.md` 以前写着有，已改口）。附带一处：重开时阅读器顶栏的编码标签是写死的 `UTF-8`（`TxtBookOpener.kt:163-174`，注释说明是有意的——缓存里已是归一化文本），所以那行字从第二次打开起就不反映源文件编码 | 探测仍可能错（边界这一类已修），错了用户没有自救入口 |
| A9 | `SPLIT_ALGORITHM_VERSION`（`TxtChapterSplitter.kt:24`）与 `SplitResult.optsHash` **没有任何消费方**，全仓只有切分器自己和它的测试引用；改切分逻辑只能手动 bump `TxtBookOpener.PIPELINE_VERSION`（2026-09-22 就是手动 2→3）。且全仓没有缓存淘汰，bump 之后旧 `txt/vN/` 留在盘上 | 忘记 bump = 修复永远读不到旧缓存的书；每次 bump 漏一份 20 MB 级缓存 |

## 4. NOT verified（诚实清单）

这些事**没有被验证过**，读上面任何"已完成"时都要带着这一条：

- **没有物理设备。** 所有 Android 验证都在 API 36 x86_64 模拟器上。因此以下都未验证：
  真实触摸手感、相机/HEIC/动图封面（只试过一张截图）、Keystore 语义、WorkManager 在系统调度下的行为、
  APK 签名与安装、明文 HTTP 的系统策略差异。
- **双设备同时写**：两台设备对同一本书做冲突的离线修改，收敛顺序（先进先出、后者胜）只做过单测。
- **进程被杀在推送中途**（outbox 的崩溃测试）没做。
- **后台 worker 路径**：M11f 的离线状态队列只走了"启动时同步"，没走 worker 触发那条路。
- **受限账户的 403 toast** 没在屏幕上真正出现过（按钮对这类账户是隐藏的）。
- 计划里也提过的一部分：Compose 交互观感、仿真翻页与色温滤镜的**实际观感**（这类只有真机眼睛能判断）。

## 5. 验证通道（这一轮怎么被验证的）

| 通道 | 命令 | 覆盖 |
| --- | --- | --- |
| 服务端全套 | `npm run verify` | typecheck + 契约一致性 + 单测 + **对 `dist/` 冒烟**（真套接字） |
| 阅读引擎 | `cd android && ./gradlew :engine-core:test` | 纯 JVM，无 SDK 也能跑 |
| App 逻辑层 | `./gradlew :core:testDebugUnitTest` | 含 Live 测试（需真实服务器，否则跳过） |
| App 产物 | `./gradlew :app:assembleDebug` | 出 APK |
| 跨语言黄金用例 | 两侧都跑 `shared/fixtures/` | 同一批字节 → 同样的编码与断章结论 |
| 容器 | `docker compose -f deploy/docker-compose.yml up --build` | 需手工跑（CI 不含此步） |
| 设备 | adb 脚本 + 模拟器 | 人手跑的，脚本不在仓库里 |

证明产物可运行。在 ①/② 真跑通之前，不说"已容器化并测试过"。
