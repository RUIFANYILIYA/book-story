# 01 · 架构

两条线，一个契约：`server/` 是权威（库元数据、文件、分类法、账号），`android/` 是客户端（读取、离线、进度）。
两者之间只有一条接口——`shared/api-spec/openapi.yaml`。服务端不假设 App 的行为，App 不依赖服务端代码。

---

## 1. 服务端

Fastify 5 + TypeScript + SQLite（`node:sqlite`），单容器、单进程、两个命名卷、无外部依赖。

### 1.1 唯一硬前提：零原生依赖

部署目标是 NAS 的 Docker，镜像要在开发机、NAS、CI 三处一致构建。任何 `node-gyp`/`libvips` 都是失败面，
所以运行时依赖树里不允许出现任何 `.node` 文件。三个通常需要原生模块的位置都被内置能力替换：

| 通常的库 | 这里的替代 | 前提 |
| --- | --- | --- |
| `better-sqlite3` | `node:sqlite`（`DatabaseSync`） | Node ≥ 22.12；本机实测 WAL / FTS5 / STRICT / json1 全通 |
| `argon2` / `bcrypt` | `node:crypto` 的 scrypt（PHC 风格自记参数） | 无 72 字节截断问题（中文长口令会踩 bcrypt 的坑） |
| `jschardet` 等编码探测 | 内置 ICU `TextDecoder` 候选集打分 | BOM → 严格 UTF-8 → GB18030/Big5/Shift_JIS/EUC-KR/windows-1252 打分 |

CI 的 `image-dependencies` job 在每次推送时用 `npm ci --omit=dev` 重装生产树，并断言其中没有 `.node`——
这条前提是被持续验证的，不是一次性口号。

### 1.2 依赖清单与各自的位置

| 用途 | 选择 | 为什么不是别的 |
| --- | --- | --- |
| HTTP | Fastify 5（multipart / static / rate-limit / helmet / cors / sensible） | `app.inject()` 的无套接字测试体验；Hono 要自己垒 multipart 与 range |
| 校验 / DTO | zod 4 | 单一真源同时给运行时校验与类型 |
| access 令牌 | jose（HS256，15 分钟） | jsonwebtoken 是 CJS + 同步 API |
| 刷新令牌 | 不透明 256-bit 随机串，库里存 SHA-256 | 可即时撤销，不需要 JTI 黑名单 |
| ZIP 容器读 | yauzl（中心目录随机访问、流式单条目、ZIP64） | adm-zip/jszip 整包进内存，300 MB CBZ 直接爆 |
| XML | fast-xml-parser 5（关实体、限长度/属性数、绝不取外部 DTD） | 入库的是任意上传文件，OPF/FB2 是攻击面 |
| 日志 | pino | — |
| 迁移 | 自写 ~80 行 runner | 见 §1.5 |
| 查询 | 仓储模块 + 预编译语句，不引查询构造器 | 30 张表的 CRUD 用生成器是过度设计 |

`croner` 曾在 `server/package.json` 里但从未被 import；周期清理任务落地时用的是 `setInterval().unref()`
（见 §1.9），所以 `croner` 已删。**`commander` 仍然只声明不使用**，它在等 `cli.ts`（`05-路线图.md` 的 S2）。

### 1.3 请求路径的四个约定

1. **响应是裸资源**，没有 `{ data }` 外壳；失败一律是 `ErrorEnvelope`，
   `code` 取自 `errors.ts` 里的封闭枚举（App 可以依赖它做分支）。
2. **能力位**：`auth/capabilities.ts` 定义 11 个能力（`library:read`、`library:edit`、`user:manage`、
   `file:upload`、`file:delete`、`book:delete`、`batch:delete`、`collections:global`、`settings:write`、
   `audit:read`、`storage:manage`）。`admin` 拥有全部，`user` 只有 `library:read` + `file:upload`；
   每条路由在 `preHandler` 声明所需能力，个人数据查询在仓储层强制 `WHERE user_id = :actor`。
   能力的封闭联合让拼错的授权在写入/启动时就报错，而不是"静默什么都没授权"。
3. **游标是 HMAC 签名的排序键 + id**（id 是时间有序的 ULID），排序键走白名单；
   客户端不能构造游标去越权翻页。
4. **校验在边界**：zod `parseWith(schema, input, 'params'|'body')`，失败即信封错误。

### 1.4 数据模型（9 个迁移）

| 迁移 | 表 | 作用 |
| --- | --- | --- |
| `0001_identity` | `users`、`auth_devices`、`login_attempts` | 账号；`auth_devices` 同时承载登录会话与离线设备，刷新令牌按 `family_id` 轮换 |
| `0002_library` | `blobs`、`categories`、`series`、`contributors`、`books`、`book_files`、`book_contributors`、`tags`、`book_tags`、`collections`、`collection_books` | 共享内容层；`categories` 物化 `path` 支持子树筛选；`collections.kind`/`rule_json` 为将来的智能分组预留 |
| `0003_personal` | `user_book_states`、`reading_positions`、`position_history`、`bookmarks` | 私有层；`user_book_states` 带单调 `rev` 游标、书架/状态、封面覆写；`reading_positions` 每 用户×文件×设备 一行 |
| `0004_ingest` | `upload_sessions`、`ingest_jobs` | 上传与入库任务状态机（分块续传的字段已预留） |
| `0005_ops` | `operation_logs`、`settings`、`app_state` | 审计、设置、单行实例状态 |
| `0006_search` | `books_fts`（FTS5 trigram）+ 同步触发器 | 检索影子表，与元数据写入同事务 |
| `0007_upload_attribution` | `books.added_by` / `added_from` | 谁以何种方式入库（`SET NULL`，删用户不删书） |
| `0008_category_root_uniqueness` | — | 修正根级分类重名约束 |
| `0009_category_two_levels` | — | 书架只允许两层：把更深的节点上提到第二层、重建 `path`，并加触发器兜底 |

四条不变量值得记住：

- **`blobs` 是内容寻址、不可变的**；同一个文件重复上传只占一份。`refcount` 存在但**只有换封面会减**
  （`files.routes.ts:201`/`:240`），删除书本并不减它——所以回收判据是可达性，不是这个计数。
- **`book_files` 的行只追加**：换文件（`mode=replace`）是插入新行并把旧行的 `is_primary` 置 0，
  旧行仍然 `status='ready'`、仍可下载（`GET /books/:id` 会把它作为另一个格式列出来）。
  唯一的例外写是保留任务把失去字节的行改成 `status='quarantined'`（见 §1.9）。
- **人工修改永不被重解析覆盖**：`pinned_fields_json` 记录被人工改过的字段；
  `metadata_source` 与 `needs_review` 让"置信度低"的东西显式排队，而不是假装解析成功。
- **书架只有两层**：`categories` 允许 `parent_id`，但只允许书架 + 子书架这一级。App 只画两层，
  第三层在任何客户端上都不可见，所以写入时就被拒绝（`validation_failed`），数据库触发器兜底。

检索：`codePointLength(q) >= 3` 走 FTS trigram，1–2 字用 `search_text LIKE ... ESCAPE` 回退
（trigram 对 2 字中文不命中）。

### 1.5 迁移：只向前，带校验和

`migrations/*.sql` 顺序执行，`schema_migrations(name, checksum)` 记录。**改动已执行过的迁移文件会导致启动失败**，
这是刻意的——否则代码与库结构会悄悄不一致。要加字段就新增一个迁移文件。

### 1.6 入库流水线

```
上传/目录导入 → 4 KB 头嗅探(+ZIP 内容判定) → sha256 → 同文件系统 rename 进 blobs/<xx>/<yy>/<sha>
             → 引用计数/去重 → 解析元数据 → 书籍 upsert（pinned 保护）→ 封面提取
```

- 解析器现状：EPUB（container→OPF→spine，含 calibre 与 EPUB3 两种系列方言）、TXT（ICU 编码探测 +
  文件名启发式）、FB2（含 base64 封面）、CBZ（自然序 / ComicInfo）、DOCX（`docProps/core.xml`）、
  PDF（尽力而为，主要靠文件名）。
- **MOBI / AZW / AZW3 / KFX 没有解析器**（`metadata/index.ts` 返回低置信度 + warning），这是已知缺口。
- 解析失败或置信度低 → 标题回落文件名 + `needs_review=1`，在 `/admin/` 里集中人工确认。
- 封面：magic bytes 判类型；无封面时生成**确定性的 SVG 占位**（书名/作者 + 由 sha 派生的配色），
  服务端不做缩放（缩略图交给浏览器/Coil 解码期降采样），这样镜像里不需要 `sharp`。

### 1.7 文件下发（App 断点续传的正确性基础）

`http/range-stream.ts` 的规则，逐条都有测试（`test/files-range.test.ts`，22 项）：

| 规则 | 内容 |
| --- | --- |
| 强 ETag | 由内容 sha256 派生，内容变则 ETag 变 |
| `If-Range` | 与强 ETag 严格比对，**不匹配就回 200 全量**——否则 App 续传出来的是静默损坏的文件 |
| 越界 | 416 + `Content-Range: bytes */total` |
| 单区间 | 只支持单 part，多区间拒绝 |
| 绝不压缩 | 该路由永不 `Content-Encoding`（gzip 会毁掉 range 语义） |
| 流式 | `fs.open` + `createReadStream({start,end})` → `stream.pipeline`，1 MiB highWaterMark，`req.on('close')` 中止；绝不整文件进内存 |
| 文件名 | `Content-Disposition: attachment; filename*=UTF-8''...`（RFC 6266/5987，中文名可靠） |

### 1.8 同步的权威划分

- **服务端权威**：库元数据、分类/分组/书架成员、推上去的封面。
- **客户端权威**：阅读位置。按 `rev` 单调计数做 LWW 合并；**跨文件版本只信 `percent`，不信 `charOffset`**
  （换文件、换字号后字符偏移没有可比性）。
- 删除一律**墓碑**（`deleted_at`），这样离线端不会把"删掉了"误判成"没同步下来"。
- `GET /sync/delta?cursor` 拉、`POST /sync/push` 推；`GET /sync/offline-manifest` 是"登录一次 → 整架可离线"的入口。

### 1.9 保留与回收（`maintenance/sweeper.ts`）

删除只写墓碑，字节的释放交给周期扫描。**判据是可达性**：一个 blob 只有在没有任何活书引用它时才退役——
活书的 `book_files(status='ready')`、`books.cover_blob_id`、任一 `user_book_states.cover_override_blob_id`、
或未终态的 `ingest_jobs.blob_id` 都算引用（`ingest.ts` 里"未挂上书本的 blob 不能被半路收走"就是这条）。

三步，各自幂等，时钟都挂在同一个 `blobs.deleted_at` 上但窗口首尾相接，所以一次扫描绝不会既移动又删除：

| 步 | 条件 | 动作 |
| --- | --- | --- |
| retire | 不可达且 `deleted_at IS NULL` | 置 `deleted_at = now`、`refcount = 0`；**文件留在原地**，半截下载继续可用 |
| reclaim | `deleted_at < now - EBOOK_FILE_RETENTION_DAYS` | `rename` 到 `trash/<blobId>`，并把指向它的行改成 `status='quarantined'` |
| purge | `deleted_at < now - (保留窗口 + 24h)` | unlink `trash/` 里的副本，这一步才真正释放磁盘 |

`retire` 后 `BlobRepo.existing()` 就不再看见这一行（它筛 `deleted_at IS NULL`），所以窗口内重新上传相同字节
会得到一条新行，而不是把退役行复活。

顺带收的：过期 `upload_sessions` 及其 `tmp/uploads/<id>` 目录（按 `expires_at` 判定——状态一翻 `updated_at`
就被重写，拿它当钟会永远追不上）、被接班且已失效的 `auth_devices` 行、终态 `ingest_jobs`，
以及一次 `PRAGMA wal_checkpoint(TRUNCATE)`（否则 -wal 只在最后一个连接关闭时收缩，长跑容器等于不收缩）。

**日志而不进请求路径**：`startSweeper` 只在 `main.ts` 里启动，`buildApp` 不碰定时器，否则每个 HTTP 测试
都要跟一个会删文件的计时器赛跑。默认每 6 小时一趟，启动 30 秒后先跑一次，两个计时器都 `unref()`。

## 2. Android

### 2.1 四模块与依赖方向

```
engine-core  纯 Kotlin/JVM：文档模型、编码探测、归一化、TXT 断章、TOC 编解码、分页器
engine-android  渲染：Paint 字形测量、Canvas ReaderView、翻页动效
core         网络(Retrofit/OkHttp) · Room · DataStore · 内容寻址存储 · 下载 · 同步 · 离线队列
app          Compose 屏幕 + Hilt + 导航 + MainActivity
```

依赖方向单向：`engine-core` ← `engine-android` ← `app`，`core` 依赖 `engine-core`，`app` 组装全部。
`settings.gradle.kts` **按 SDK 是否可用来条件包含** `:core`/`:engine-android`/`:app`，`:engine-core` 永远包含——
于是 `./gradlew :engine-core:test` 在只有 JDK 的机器上是绿的，最难的分页与断章逻辑先被验证。

### 2.2 格式无关的中间模型 + 两个接缝

```
Block（Paragraph/Heading/ImageBlock/Quote/BulletList/Preformatted/HorizontalRule/PageBreak/FootnoteRef）
Chapter(index, title, level, charStart, charEnd, ...)
PlacedLine(start, end, baseline, advance, justifyGaps, kind)
Page(lines, firstChar, lastChar)          Anchor(chapterIndex, charOffset)
LayoutKey(chapterId, docSha, 内容宽高, 字体, 字号, 行距, 边距, 主题度量)
```

- 接缝一：`GlyphMeasurer`（纯 JVM 测试里可以给假实现，Android 上是 Paint 实现）。
- 接缝二：`PageMotion`（无动画 / 滑动 / 覆盖；**仿真翻页是二轮**，接口先留好）。
- 阅读主题只作用于 layout/draw，不污染文档模型：**改设置 = 换 `LayoutKey` 重排，不重新解析**。

### 2.3 阅读位置

位置锚点是 `Anchor(chapterIndex, charOffset)`，跨设备同步只走 `percent`（字符进度，跨字号稳定）。
「改字号不丢位」靠"序章位置的锚点 + 重排后二分查找"实现，这是 M10 验收的核心项。

### 2.4 本地存储

- 文件：`filesDir/objects/<sha[0..2]>/<sha>.bin`，**内容寻址**——同书重复零额外占用，服务端换文件天然失效。
- Room（v5）：`books`、`library_remote_keys`、`download_task`、`reading_position`、`sync_outbox`、
  `sync_state`、`shelf_edit`。**书签、章节、页面缓存三张表还没建**（`EbookdDatabase.kt` 里写明了）。
- 令牌：access 只在内存；refresh 用 Android Keystore 的 AES-256-GCM 包裹后写 `noBackupFilesDir`
  （不用已废弃的 `EncryptedSharedPreferences`）。

## 3. 横切：契约与跨语言用例

- **契约工作流**：`shared/api-spec/openapi.yaml` 是线格式唯真源 → `npm run contract:gen` 生成
  `contract.json`（提交进仓库）→ `npm run contract:check` 挡住"规范 ↔ 已提交清单 ↔ 服务端错误码表"之间的漂移。
  `/api/v1` 内只允许**追加**：新增可选字段、新增端点、新增枚举值；删除或改名必须开 `/api/v2` 并行提供。
- **跨语言黄金用例**：`shared/fixtures/txt-chapters/` 的同一批样本（章回体 / 网文 `第N章` / `Chapter N` /
  带页码目录 / GB18030 / UTF-16 / 页脚污染 / 假阳性诱饵）既跑服务端 vitest 又跑 `:engine-core:test`，
  两边对同一批字节必须得出同样的编码与断章结论。
- **已知漂移**：`GET /api/v1/books/facets` 已实现但没有进 `openapi.yaml`；`contract:check` 只校验
  "规范 → 清单 → 错误码"三个方向，抓不到服务端**多出来**的端点。详见 `02-API.md` 与遗留项台账。
